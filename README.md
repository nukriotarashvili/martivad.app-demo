# martivad.app — demo

ბუღალტრული აღრიცხვის დემო აპლიკაცია ქართული ბიზნესისთვის. მუშაობს მთლიანად
ბრაუზერში: სერვერი, ბაზა და რეგისტრაცია არ სჭირდება, მონაცემები არსად არ იგზავნება.

**დემო:** https://martivad-app-demo.vercel.app/

## მეთოდოლოგია

* ანგარიშთა გეგმა — საქართველოს ბუღალტრული აღრიცხვის სტანდარტების 9-კლასიანი გეგმა (114 ანგარიში).
* აღრიცხვა — IFRS for SMEs, დარიცხვის მეთოდი.
* სასაქონლო მარაგი — საშუალო შეწონილი, პერიოდული (§13.18); პერიოდი კალენდარული თვეა.
* უცხოური ვალუტა — ანგარიშიდან გასვლა მოძრავი საშუალო კურსით; წინასწარი გადახდა
  არამონეტარულია და ფიქსირდება გადახდის კურსით (§30.9).
* დღგ — განაკვეთი ორგანიზაციის პროფილში, ნაგულისხმევად 18% (სსკ მუხ. 168).

## ტექნიკური მხარე

არანაირი build, არანაირი დამოკიდებულება — მხოლოდ სტატიკური ფაილები:

```
index.html
assets/
  app.js         ინტერფეისი (ES module)
  store.js       ორგანიზაციების საცავი (localStorage)
  backup.js      სარეზერვო ასლის შეხსენება (ცალკე localStorage გასაღები)
  importers.js   ამონაწერი და რეალიზაციის რეპორტი → გატარებები
  sheetread.js   .xlsx (ZIP+XML), .xls (OLE2+BIFF8) და .csv წამკითხველი
  coa.js         ანგარიშთა გეგმა
  styles.css     გაფორმება (ღია და ბნელი თემა), DESIGN-TOKENS-C1 ცვლადები
  fonts/         FiraGO (self-hosted woff2, ka+Latin) — იგივე, რაც martivad.app-ში
```

ტიპოგრაფიისა და ფერების ცვლადები განზრახ ემთხვევა მთავარი აპლიკაციის ტოკენ-
სისტემას (`--surface-*`, `--space-*`). დიზაინის განახლებისას მხოლოდ მნიშვნელობები
იცვლება — ორივე აპლიკაცია ერთად „გადაიღებება". ლოკალური სახელები
(`--paper`, `--card`, `--ink`…) შენარჩუნებულია, მაგრამ ისინი ახლა ალიასებია.

`sheetread.js` ექსელის ფაილებს ბრაუზერშივე შლის — `.xlsx` ZIP-ის სახით
(`DecompressionStream`), `.xls` კი OLE2 კონტეინერიდან BIFF8 ჩანაწერების დონეზე.
გარე ბიბლიოთეკა არსად არ გამოიყენება.

### ლოკალურად გაშვება

```bash
git clone https://github.com/nukriotarashvili/martivad.app-demo.git
cd martivad.app-demo
python3 -m http.server 8000
# გახსენით http://localhost:8000
```

ES module-ების გამო `index.html`-ის პირდაპირ ფაილიდან გახსნა (`file://`) არ მუშაობს —
საჭიროა ლოკალური სერვერი.

### ჰოსტინგი — Vercel

პროექტს build არ სჭირდება, ამიტომ Vercel-ზე ატანა ორ ნაბიჯშია:

1. [vercel.com/new](https://vercel.com/new) → **Import Git Repository** → ეს რეპოზიტორია.
2. Framework Preset: **Other**. Build Command და Output Directory ცარიელი დატოვეთ —
   `vercel.json` თავად აწესებს ყველაფერს.

ამის შემდეგ `main`-ში ყოველი push ავტომატურად ქვეყნდება, pull request კი
თავის preview-ბმულს იღებს.

CLI-ით:

```bash
npm i -g vercel
vercel          # preview
vercel --prod   # production
```

**`vercel.json`** აწესებს: `cleanUrls`, უსაფრთხოების სათაურები და
Content-Security-Policy (`script-src 'self'`, შრიფტები მხოლოდ Google Fonts-იდან,
გარე კავშირები დაბლოკილია), ასევე `must-revalidate` — რომ განახლება მაშინვე
გამოჩნდეს ქეშის გასუფთავების გარეშე.

<details><summary>GitHub Pages ალტერნატივად</summary>

`.github/workflows/pages.yml` შენარჩუნებულია, მაგრამ ხელით ეშვება. საჭიროებისას:
Settings → Pages → Source: **GitHub Actions**, შემდეგ Actions → *Deploy to GitHub Pages* → **Run workflow**.

## შეზღუდვები

დემო ვერსიაა: მონაცემები ბრაუზერის localStorage-შია, ანუ მოწყობილობაზეა მიბმული
და ბრაუზერის მეხსიერების გასუფთავებისას იშლება. რეგულარულად გააკეთეთ JSON ექსპორტი.
მრავალმომხმარებლიანი მუშაობა, უფლებები და ავტომატური სარეზერვო ასლი
**martivad.app**-ის სრულ ვერსიაშია.

### სარეზერვო ასლის შეხსენება

რადგან მონაცემები მხოლოდ ბრაუზერშია, `backup.js` თვალს ადევნებს ბოლო ექსპორტს:

- **პირველ გახსნაზე** — ერთჯერადი, დახურვადი ბანერი იმის შესახებ, რომ cache-ის
  გაწმენდა მონაცემებს შლის;
- **≥7 დღე ბოლო სრული ექსპორტიდან** და მას შემდეგ ახალი გატარებები დაემატა →
  შეხსენება პირდაპირ ბანერში მოთავსებული „ექსპორტი" ღილაკით;
- **დახურვის შემდეგ** 7 დღე აღარ ჩნდება;
- **თვის დახურვის შემდეგ** წარმატების შეტყობინებას ემატება ასლის შეთავაზება.

ათვლას ანულებს მხოლოდ **სრული** ასლი („ყველაფრის ექსპორტი (JSON)") — ერთი
ორგანიზაციის CSV/JSON ნაწილობრივია და შეხსენებას არ თიშავს.

მდგომარეობა ცალკე გასაღებშია (`martivad.backup.v1`), რომ JSON-იმპორტმა —
რომელიც `martivad.v1`-ს მთლიანად ცვლის — შეხსენების ისტორია არ წაშალოს.

შესამოწმებლად, კონსოლში:

```js
martivadBackup.rewind(8)   // ბოლო ექსპორტი 8 დღით უკან → შეხსენება გამოჩნდება
martivadBackup.reset()     // სრული განულება → პირველი გახსნის ბანერი
```
